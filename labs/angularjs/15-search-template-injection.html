Lab 15: Greeting (AngularJS)

Source: location.searchSink: AngularJS expressionAngularJS 1.8.3

What is happening

The script puts your name on the page with textContent, the safe way from lab 01. Then AngularJS starts up and scans the page for {{ ... }}. Your input is now part of an Angular template, and Angular runs whatever is inside the braces.

Why this is a sink

This is client-side template injection. No HTML is injected, so HTML encoding does not help. The danger is the {{ }} itself. Angular expressions can reach the Function constructor, and from there run any JavaScript.

AngularJS 1.5 and older had an expression "sandbox" that tried to block exactly this. It was broken and re-broken for years — see PortSwigger's own research on AngularJS sandbox escapes for how many different ways researchers found around it. The Angular team eventually agreed it was never a real security boundary and removed it entirely in 1.6, partly for the performance cost of maintaining it. On 1.6 and newer, the simple payload below works with no sandbox to get around at all.

Payload 
{{constructor.constructor('alert(1)')()}}
Fix
  • Never let user input end up inside an element Angular will compile.
  • Add ng-non-bindable to elements that show user data. Angular skips them.
  • Upgrade. The real fix is moving off AngularJS, which is end of life.
