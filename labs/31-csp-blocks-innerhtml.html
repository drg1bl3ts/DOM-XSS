Lab 31: Bio, with a Content-Security-Policy (safe, for this payload)

Source: location.searchSink: innerHTML (mitigated by CSP)

What is happening

This page has the exact same vulnerable code as lab 01: bio goes straight into innerHTML, no sanitizing at all. The only difference is the Content-Security-Policy on this page, visible in the <meta> tag at the top of the file: script-src 'self'.

Try the usual payload

Submit <img src=x onerror=alert(1)>, the same one that works on lab 01. Nothing happens here.

Why it's blocked

An onerror attribute is, as far as the browser is concerned, inline script. script-src 'self' means "only run script from this page's own origin," and inline script doesn't come from a URL at all, so it's refused unless the policy explicitly allows it with 'unsafe-inline', a hash, or a nonce. Open the browser console and you'll see the actual CSP violation message Chrome prints when it blocks this. The same policy blocks a javascript: URL in an href, and blocks eval() too unless 'unsafe-eval' is added.

This isn't a full fix

CSP is blocking this specific technique, not the underlying bug: the string is still inserted as real HTML with no sanitizing. Lab 32 shows a technique this exact policy does nothing about. Treat CSP as a strong extra layer, not a replacement for fixing the sink.
