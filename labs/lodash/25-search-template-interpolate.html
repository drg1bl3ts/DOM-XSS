Lab 25: Bio (Lodash)

Source: location.searchSink: _.template with <%= %>Lodash 4.17

What is happening

_.template() compiles a string with embedded placeholders into a function that builds HTML. The template here is <p><%= bio %></p>, and the result is written with innerHTML.

Why <%= %> is a sink

Lodash templates have three delimiters, and their names are easy to mix up: <%- %> "escape" HTML-encodes the value, which is the safe one, despite sounding like it might strip the escaping instead of adding it. <%= %> "interpolate" inserts the value exactly as given, with no encoding at all. <% %> "evaluate" runs raw JavaScript inside the template. Verified directly against the library in this hub, not from memory: it's worth checking the actual behaviour of a templating engine's delimiters before trusting your recollection of which one is which, since (as happened while writing this lab) it's an easy pair to swap.

Payload 
<img src=x onerror=alert(1)>
Fix 
_.template("<p><%- bio %></p>")

Use <%- %> instead, which HTML-encodes the value.

This hub originally shipped Lodash 4.17.21, which CVE-2026-4800 affects: a different _.template bug, code injection through the imports option, fixed in 4.18.0 and since upgraded to here. This lab doesn't use imports, so it isn't the same bug as the one above, but there's no reason to ship the vulnerable version regardless.
