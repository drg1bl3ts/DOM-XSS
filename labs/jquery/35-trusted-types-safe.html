Lab 35: Bio, jQuery 4.0 under Trusted Types (safe)

Source: location.searchSink: $.html() (blocked by Trusted Types)jQuery 4.0.0

What is happening

Same vulnerable-looking line as lab 11: $("#profile").html(bio), a raw string, no sanitizing. This page's Content-Security-Policy requires Trusted Types for scripts, same as lab 33. Submit the usual payload and the status line shows the assignment throwing instead of succeeding.

jQuery had to catch up to this

This only works because jQuery 4.0 (released very recently) added Trusted Types support. Verified directly, side by side: loading jQuery 3.7.1 — the version used elsewhere in this hub until this lab was built — on a page with this exact same CSP doesn't just leave .html() unprotected, it fails to load at all. Its own internal feature-detection code assigns a raw string to innerHTML while jQuery is still setting itself up, before anything of yours has run, and that throws under enforcement, so window.jQuery is never defined. jQuery 4.0's own code was updated to avoid that, which is what makes a page like this one possible at all.

Payload 
<img src=x onerror=alert(1)>

The status line shows the real TypeError the browser throws.

The lesson

Trusted Types doesn't just protect your own code, it protects you from your dependencies' code too, but only if those dependencies were built to expect it. An older, still-very-common version of one of the most widely used libraries on the web couldn't even load on a page that enforces it. If you're rolling out Trusted Types on a real site, check every library you load, not just your own sinks.
