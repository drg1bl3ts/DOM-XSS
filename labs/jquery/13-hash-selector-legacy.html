Lab 13: Scroll to section (legacy jQuery)

Source: location.hashSink: $(selector)jQuery 1.6.1

Try 13-hash-selector-legacy.html#intro and reload.

Intro

What is happening

The script passes location.hash straight to $() to find the section named in the URL. This is a very common pattern: $(location.hash).

Why $() is a sink

$() does two jobs: find elements from a selector, or create elements from an HTML string. jQuery guesses which one by looking at the string. jQuery 1.6.1, used in this lab, decided "this is HTML" for any string containing <...>, even if it started with #. So a hash like #<img ...> created an element. Confirmed directly: trying the same string in 1.7.2 and 1.9.0 instead throws a selector syntax error, so the fix landed somewhere between 1.6.1 and 1.7.2 — tracked as CVE-2012-6708.

As of jQuery's own 1.9 upgrade guide, a string is only ever treated as HTML if it starts with <, full stop, so this exact bug is gone for good from 1.9 on. Old jQuery still turns up in legacy apps, so look for the library version when you test a real site.

Payload 
13-hash-selector-legacy.html#<img src=x onerror=alert(1)>

Reload after changing the hash, because the script only runs once on load.

Fix
  • Upgrade jQuery.
  • Check the hash first: if (/^#[\w-]+$/.test(location.hash)) { ... }
