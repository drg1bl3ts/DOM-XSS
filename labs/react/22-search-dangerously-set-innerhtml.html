Lab 22: Bio (React)

Source: location.searchSink: dangerouslySetInnerHTMLReact 18

What is happening

This page uses plain React, no build step, no JSX: just React.createElement calls, loaded straight from local copies of the React and ReactDOM scripts.

Normally React treats everything you give it as text. A line like React.createElement('p', null, bio) is always safe, no matter what bio contains, because React calls textContent under the hood, the same as the fix in lab 01. dangerouslySetInnerHTML is the one prop that turns this off.

Why dangerouslySetInnerHTML is a sink

It takes an object { __html: string } and sets the element's real innerHTML to that string, parsed as HTML. React's own docs say the awkward name and the extra wrapper object are deliberate, "to make the security risk explicit" — their own example of the danger is an untrusted post.content string containing exactly the kind of onerror payload used throughout this hub. Verified directly: it still doesn't run <script> tags, for the same reason plain innerHTML doesn't.

Payload 
<img src=x onerror=alert(1)>
Fix 
React.createElement('div', { className: 'output' }, bio)

Pass the string as a normal child instead of through dangerouslySetInnerHTML.
