Source: location.searchSink: bypassSecurityTrustHtmlAngular 22

What is happening

Same idea as lab 18, except the component wraps the value in sanitizer.bypassSecurityTrustHtml() before handing it to [innerHTML]. That call tells Angular "trust me, I already checked this string." Nobody did.

Why bypassSecurityTrust* is a sink

Angular's DomSanitizer has four of these: bypassSecurityTrustHtml, Style, Url, ResourceUrl, and Script. They exist for real cases, like showing HTML from a trusted CMS or a WYSIWYG editor's own output. The bug is calling one of them on data that came from a user or the URL. In real code, search for bypassSecurityTrust the way you would search for eval; it is a short, grep-able list of every place the sanitizer was turned off.

Payload 
<img src=x onerror=alert(1)>
Fix

Do not bypass. Let the default sanitizer run, like lab 18, or sanitize the value yourself with a trusted library before this point.
