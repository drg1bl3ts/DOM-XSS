Lab 21: Bio via raw DOM access (modern Angular)

Source: location.searchSink: ElementRef.nativeElement.innerHTMLAngular 22

What is happening

The component grabs a real DOM reference with @ViewChild and sets .innerHTML on it directly, the exact same plain-JavaScript sink as lab 01 at the start of this hub.

Why this matters

Angular's automatic sanitizing only covers Angular's own bindings: [innerHTML], [href], and a few others written in a template. It cannot protect code that reaches into the DOM directly through ElementRef, Renderer2 used unsafely, or a native browser API. A framework's safety net only covers the doors it built; a component that goes around the template layer is on its own again, exactly like plain JavaScript.

Payload 
<img src=x onerror=alert(1)>
Fix 
this.box.nativeElement.textContent = bio;

Or better, avoid ElementRef.nativeElement for content and use a normal template binding instead, so Angular's sanitizer is back in the loop.
